## 1. 项目做什么

人站在离笔记本约 1.2 m 的地方做手势,协作机械臂做对应的预设动作。摄像头是笔记本自带的 RGB,
没有深度。机械臂在动时,画面里任何人张开手掌朝镜头,或者在笔记本上按空格,它就停。

| 项 | 现状 |
|---|---|
| 机械臂 | JAKA Zu 20(控制柜 1.7.2),仿真和真机都跑过;Dobot Nova 5 只在仿真里跑 |
| 摄像头 | 笔记本自带,0 号,1280×720,30 fps |
| 识别 | HaGRID 团队的 `dynamic_gestures`:手部检测和姿势分类两个 ONNX 模型,onnxruntime,只用 CPU |
| 控制机械臂 | RoboDK 5.9 的 Python API。仿真和真机共用一份代码,真机经 RoboDK 的 JAKA 驱动 |
| 环境 | Python 3.13,uv 管依赖,Windows 11 |

**默认只动仿真。**连真机必须在启动时加 `--real`,并用 `--arm` 指明填了控制柜 IP 的那份配置
(IP 不进仓库,配置副本放在仓库外)。

手势和预设动作的对应写在 `config/demo.toml` 里,改对应关系不用改代码:

| 触发手势 | 怎么做 | 预设动作 |
|---|---|---|
| 握拳平移 左 / 右 | 拳头在起点区停住,朝左 / 右移过约 1.5 个拳头 | 左 / 右挪 150 mm |
| 握拳平移 上 / 下 | 同上,朝上 / 下 | 上 / 下挪 100 mm |
| 往前推 | 拳头停住,往镜头推出去约 20 cm | 远离操作者挪 100 mm |
| 敲两下 | 拳头停住,像敲桌子那样往下点两下 | 朝操作者挪 100 mm |
| 保持比 V | 在起点区保持约 1 秒 | 画方块 |
| 保持竖拇指 | 同上 | 原地点头 |
| 保持 OK | 同上 | 鞠躬 |
| 保持 rock | 同上 | 回待命 |
| 张开手掌 / 空格 | 机械臂在动时,画面里任何人做都算 | 叫停 |

**有意不做的:**连续遥操作(手到哪、机械臂跟到哪,ADR-0001)、手的 3D 位置、身体识别、碰撞检查、
Dobot 真机。

## 2. 整体架构

### 2.1 一帧画面怎么变成机械臂的动作

```
摄像头
 → 取帧 frames:1280×720,水平翻转一次
 → 识别器 gestures:检测 + 跟踪 + 分类,给出每只手的手框、姿势标签、跟踪编号
 → 触发判定 triggers:握拳平移 / 姿势保持 / 停止手势
     ├ 触发手势 → 状态逻辑的事件队列 state → 执行线程逐段下发 executor → 机械臂接口 arm
     └ 停止手势 → 叫停通道 stop → 机械臂接口的「停止」(空格也走这一条)

机械臂接口 arm
 → RoboDK 实现 → 仿真里的模型
                 └ 加 --real 时:经 JAKA 驱动 → 控制柜
```

两条路故意分开:触发要经过状态逻辑(冷却、执行中都不受理),**叫停不经过任何人**,谁先发现
谁直接调机械臂的「停止」(ADR-0012)。

### 2.2 三个缝

全项目只有三处可以替换的接口。测试、回放、不开 RoboDK 跑,全靠换这三处:

| 缝 | 接口 | 实现 |
|---|---|---|
| 取帧 | `vision_side.frames.FrameSource` | 摄像头、视频文件(回放)、编好的帧(测试) |
| 识别结果 | `vision_side.recognize.Recognizer` | 真识别器、逐帧日志回放、编好的结果(测试) |
| 机械臂接口 | `robot_side.arm.Arm` | RoboDK 实现(仿真 / 真机)、空实现(不开 RoboDK)、假机械臂(只在测试里) |

输出一侧不另开缝:触发走状态逻辑已有的事件队列(和调试按键同一条),叫停走叫停通道(和空格同一条)。

### 2.3 线程

| 线程 | 做什么 |
|---|---|
| 识别线程 | 取帧 → 识别 → 触发判定;触发手势排进事件队列,停止手势就地叫停 |
| 主线程 | 状态逻辑、预览窗口(Tk)、键盘、识别中断判定 |
| 执行线程 | 一次只发一段运动,等它走完;发下一段前先看「已叫停」标记 |
| 按键线程 | 每 10 ms 用 Windows 的 `GetAsyncKeyState` 查一次空格,窗口不在前台也有效 |
| 提示音、日志 | 各一个线程,不阻塞主线程 |

这样拆是因为主线程实测会卡:拖预览窗口的标题栏,同一线程停过 6.8 秒;站着录像时没拖窗口也卡过
6 次。所以识别和窗口分线程,叫停不经过主线程。

## 4. 实现方法

### 4.1 手势识别

- **识别器选 `dynamic_gestures`**(ADR-0002)。它用一套检测、跟踪(OC-SORT)、分类流水线,给出每只手
  逐帧的手框、姿势标签(HaGRID 的类别)和跟踪编号。没选 MediaPipe Gesture Recognizer,因为它开箱
  只有 7 类静态手势。
- **只用逐帧结果,上游的动态手势事件不用**(ADR-0007)。第一轮原型里上游 6 个触发手势只有「点击」
  可靠,而点击又是自由活动时误触发的主要来源。触发规则改成自己写(4.3)。
- **上游代码复制进项目,带三处修补:**numpy ≥ 2.4 时 `w / float(h)` 改成 `w / h`(否则跟丢再匹配
  会崩);关掉 onnxruntime 的线程自旋(否则有手时只有 9–15 fps,关掉后稳定 30 fps);
  `provider_options` 为空时不传。
- **画面先水平翻转一次再识别**,不翻转时带方向的姿势标签会左右对调。
- **操作距离 1–1.5 m,取 1280×720**(ADR-0006)。坐在笔记本前约 40 cm 时姿势标签正确率只有 14%,
  1.2 m 处是测过的条件里最好的。
- **只把操作位周围约 800×600 的检测区域送检测器**(ADR-0008)。检测器会把送进去的画面缩到
  320×240,1.2 m 处约 86 px 宽的拳头在整幅画面里只剩约 21 px,在检测区域里约 34 px。只改这一处,
  握拳平移四个方向从 7/6/7/5 升到 9/8/10/9,判反从 2 次降到 0。执行中、回待命、已停止时改送
  整幅画面,好让站在区域外的人也能叫停。

### 4.2 启动对准

1. 操作者站到操作位,把拳头举起来(举在哪儿都行)。整幅画面里找拳头,停稳约 1.2 秒:手框中心移动
   不超过半个手宽,至少八成帧是握拳类标签。
2. 以拳头为中心放下 800×600 的检测区域(超出画面就贴边),切过去以后再量约 0.8 秒,取拳头手框宽
   的中位数作**手宽**。整幅画面里量到的宽和检测区域里的差 1–16% 不等,不能按比例折算,
   所以手宽一律用检测区域里量的。
3. 以同一点为中心放下**起点区**,边长 3 个手宽。响一声、画出边框,自动往下走。
4. 整幅画面里拳头宽超过约 107 px(1.2 m 参考值的 1.25 倍)时提示 TOO CLOSE,只提示,不拦着。

这一步在连机械臂之前做完:机械臂连上后第一件事就是回待命,那时停止手势必须已经能用。
空闲时按 R 可以重新对准。

### 4.3 触发判定

三套规则互不相干,吃同一份逐帧结果(`vision_side/triggers.py`)。参数全在演示配置的 `[vision]`
一节,是六轮原型扫参后的初值;改了就要重跑回放测试。

**握拳平移**(ADR-0009、ADR-0010)

1. **停住段:**约 0.3 秒里手框中心晃动不超过半个手宽,至少八成帧是握拳类标签
   (`fist`、`grip`、`point`、`little_finger`、`fist_inverted`,移动中的拳头常被认成后几个),
   而且停在起点区里。成立就亮 READY,并**锁定**这只手的跟踪编号。
2. **移动段:**1.2 秒内移过 1.5 个手宽,至少六成帧是握拳类标签,主方向位移至少是另一方向的 3 倍。
   方向按手框的实际位移判,不看带方向的姿势标签。
3. **收手抑制:**触发前 1.5 秒内手朝反方向动过,这次不算。

锁定之后只看这一只手,别的手一律不管。锁定在三种情况下解除:READY 之后过了 1.2 秒;触发了一次
(含被收手抑制挡掉的);清空判定记录。锁定的手一时看不见,锁定不解除,只把 READY 变暗。

**往前推、敲两下**(ADR-0015)也挂在同一个锁定上:

- **往前推**看手框变大:从最近 1.2 秒里拳头(连远近也)停住、手框最小的那一刻量起,手框宽到
  1.4 倍、高到 1.2 倍,连着 3 帧,都是握拳类标签。只看宽不够,食指往旁边一指手框也会变宽。
- **敲两下**看手框中心上下:一下是往下 0.4 个手宽、再抬回 0.3 个手宽,3 秒内第二下往下一过门槛
  就算。手宽按最近停住时的手框宽量,因为往前推完拳头离镜头近,手框能大一倍。

**姿势保持**(ADR-0007):只看起点区里最大的那只手,不用锁定。约 1 秒里至少八成帧是同一个姿势
(没有手的帧也算在分母里)就触发。触发过后要先**松开**(这个姿势连续约 0.3 秒没被认出)才能再
触发,而且松开之后只算松开之后的帧。

**停止手势**(ADR-0012):`palm`、`stop`、`stop_inverted`、`three`、`four` 任一都算(张开的手常被
认成 three、four)。按整幅画面计,任何一只手、任何人做都算,不受锁定影响,连续 3 帧成立。只在
「从没认到变成认到」那一下叫停一次,否则手一直举着会被当成回待命途中又叫停,直接进已停止。

**这么多条规则,每一条都是为挡一种实测出来的误触发加的。**误触发比漏认危险:漏认只是机械臂不动,
误触发会让它朝错的方向动。

| 误触发 | 原型里实测 | 怎么挡 |
|---|---|---|
| 挪拳误触发:把拳头挪到起点、抬拳准备时被当成一次平移 | 40 次里 5–7 次 | 起点区(ADR-0009) |
| 换手误触发:另一只手抬到脸前,「最大的手」一跳被当成平移 | 16 次里 7 次 | 锁定(ADR-0010) |
| 判反:动作没认出,紧接着的收手被当成反方向 | 2 次 | 检测区域 + 收手抑制 |
| 拼接误触发:执行中做的半个手势和进空闲后的半个连成一次 | 1 秒冷却时 5 次漏 1 次 | 进空闲先清记录,再冷却 2 秒 |
| 顺手误触发:扶眼镜时在区里被认成握拳,随后手移开 | 偶发 | 不专门挡;靠冷却、慢速、停止手势和急停兜底 |

### 4.4 状态逻辑

五个状态:空闲(IDLE)、冷却(COOLDOWN)、执行中(RUNNING)、回待命(RETURNING)、已停止(HALTED)。

```
启动 → 回待命(倒计时 3 秒 → 抬起 → 回待命位姿)→ 冷却 → 空闲
空闲 + 触发手势 → 执行中 → 走完,停在新的停靠点 → 冷却 → 空闲
空闲 / 冷却 + 按 H 或做 rock → 回待命 → 冷却 → 空闲
执行中 + 叫停 → 回待命 → 冷却 → 空闲
回待命 + 叫停 → 已停止 → 按回车 → 清除报错 → 回待命
机械臂报错 / 某段超时 / 不在停靠点 / RoboDK 断开 / 识别中断 → 已停止
```

- **执行中只认叫停**,别的手势既不打断也不排队。
- **进冷却前清空判定记录**,冷却期间不受理触发手势,挡拼接误触发。
- **已停止要人回到笔记本前按回车**才出得来;恢复时先清报错,必要时提示去示教器上重新上电使能,
  再走回待命。清不掉的(比如连接断了)就留在已停止,只能重启程序。
- **识别中断**:执行中或回待命途中超过 0.5 秒拿不到新的识别结果,或画面连续约 0.5 秒几乎是一片
  均匀颜色(摄像头隐私开关关着时的占位图、全黑),就进已停止,因为这时看不见停止手势了。
  画面正常、只是没有手,不算。
- **叫停不走事件队列。**主线程每轮只看叫停通道上多了几条记录,再切状态、刷新画面。按条数认,
  不按标记认:标记每次发运动前会被放下,条数只增不减,连按两下空格也漏不掉。

### 4.5 坐标、路点和运动

- **工作台坐标系**(ADR-0003):+X 指向操作者右手边,+Y 远离操作者,+Z 竖直向上;相对机械臂基坐标系
  只绕 Z 转一个角度,可再加原点平移。换机械臂只重新标这个角度,路点照用。JAKA 的 90° 是按现场
  布置定的,没有示教。
- **路点按法兰,不按指针尖端**(ADR-0013):控制器保持工具 0,指针偏移只作参考。这样和用户平时下
  指令的方式一致,标定也少一步。
- **待命位姿用一组关节角**,保证每次回到同一个关节构型;**待命点**是它的正解。
- **预设动作从停靠点出发,做完不回待命**(ADR-0014)。路点写成相对出发点的偏移。`end = "stay"`
  的(左右上下前后)停在最后一个路点上,可以叠加;`end = "back"` 的(画方块、点头、鞠躬)做完回到
  出发点。
- **活动范围**:停靠点离待命点最多左右 300 mm、前后 100 mm、上下 200 mm,一共 5 × 3 × 5 = 75 个
  停靠点。做完会停到范围外的,这一次不动,屏幕显示 OUT OF RANGE。
- **拆段**(`motion.py`):每个路点一段直线;改姿态的段(点头、鞠躬)走关节运动;回待命是先沿 +Z
  抬起 50 mm、再回待命位姿,两段都是关节运动。
- **速度**:每个预设动作一个 `speed_mms`。直线段法兰按它走,关节段按「指针尖端也走这么快」现算
  关节速度,不超过机械臂配置里的上限。仿真里就是这个速度;真机见 4.8。

### 4.6 下发和叫停

- **一次只发一段**(`executor.py`)。非阻塞发出,轮询「还在动吗」,停了才发下一段。上一段没走完
  就发下一段,会占住连接,同一条连接上的叫停也被卡住;另外程序崩了,机械臂最多走完当前这一段。
- **发每一段之前先看「已叫停」标记和机械臂身上挂没挂报错。**叫停可能正好落在两段之间,那时
  「停止」没东西可停,只能靠标记拦住下一段。
- **每段等多久算超时:**估算用时 × 2 + 5 秒,超了进已停止。
- **运动中不读关节角**:第一次上 JAKA 时这样做让 RoboDK 5.9 崩了进程。
- **判「走完了」:**只跑仿真时信 RoboDK 的 `Busy()`;连着真机时 `Busy()` 不可信,要读回位姿核对
  确实到了目标。
- **叫停**:先立「已叫停」标记,再调机械臂的「停止」,顺序不能反。「停止」可从任何线程调,
  重复调没有副作用。验收标准是拖住预览窗口不放时按空格,机械臂照样 0.5 秒内停住。

### 4.7 可达性检查

- **每个路点求逆解,再用正解核对、反复迭代。**JAKA 的逆解是数值迭代的,不收敛也会返回结果,
  不能把「有返回」当成够得着。
- **每段直线单独查**,中途过奇异点、超关节限位都报出来。下一段起点的关节角接着上一个点求,
  不读回机械臂。
- **不查碰撞**:启动时关掉 RoboDK 的碰撞检查,退出时恢复原设置。
- **什么时候查:**启动时查从待命点出发的全部动作,不过就指出是哪个动作的第几个路点,全程不动
  机械臂。从别的停靠点出发的,第一次执行前再查,查过的记住,不过就显示 CAN'T REACH。
- **连真机之前**把 75 个停靠点出发的每个动作全查一遍(JAKA 上要几分钟),结果按指纹
  存进 `data/cache/`。指纹只含决定够不够得着的东西:机械臂型号、待命位姿、工作台坐标系、默认姿态、
  活动范围、各动作的路点、工作站文件、检查算法的版本号。速度、控制柜 IP 不算在内,所以改速度不用
  重查,仿真里查过的结果真机上照用。

### 4.8 连真机

启动顺序(`real.py`、`app.py`),哪一步不过就停下,不降级、不重试:

```
打开工作站 → 写入配置 → 可达性检查 + 活动范围全查(这时还没连真机)
→ 经 RoboDK 驱动连控制柜 → 查上电使能(只查不做)→ 热身 → 回待命 → 空闲
```

- **上电使能只查不做**,由人在示教器上做。查法是经 RoboDK 自带的 Python 3.10 调 `jkrc` 读状态位
  (项目的 3.13 import 不了 `jkrc`);读不出来也当成没使能。
- **热身**:发一条零行程的关节运动。`jkrc` 登录以后,连上的第一条指令要迟到约 20 秒,先把这笔
  付掉。
- **连着真机时不往 RoboDK 写配置。**写配置会设 RoboDK 里的坐标系和工具,驱动有可能把它推到
  控制柜,改掉别人也在用的工具 0 和 0 号坐标系;没验过,就按最坏的算。
- **护栏**(`guard.py`):把目标放进工作站,再**从那个目标身上读回来**逐轴核对;只动该动的轴;
  每轴、每段直线都卡行程上限。第一次上 JAKA 时差点出事:护栏只核对了算出来的目标,没核对指令里
  真正指向的点,目标要是没改成功,J1 会从 201° 甩到 1°。
- **掉线判断不只看一个返回值**(`LinkMonitor`),RoboDK 被关掉也当成断开,之后不再下发任何东西。
- **姿态镜像**:经 RoboDK 的 JAKA 驱动下发直线运动时,姿态 `(RX, RY, RZ)` 会被执行成
  `(RX, −RY, −RZ)`。对策是把待命位姿的 J6 转一下,让基坐标系里 RY = RZ = 0,正好落在镜像的不动点上
  (`standby.py`、`set_standby` 脚本)。
- **速度**(ADR-0011 的两次更新):9-20 第一次上 JAKA 时,经 RoboDK 设速度的四条通道全部无效;
  9-23 反编译驱动才发现它每收到一行指令都把速度重置成写死的 100。于是包了一层驱动
  (`drivers/jaka_keep_speed.py`,由 RoboDK 的嵌入式 Python 跑)。机械臂配置里
  `program_sets_speed = true` 时,实际速度 = 配置里的速度 × 示教器上的速度倍率;没开时快慢全看
  示教器。上真机先跑 `speed_check` 确认受控,再打开这个开关。
- **RoboDK 同一时间只让一个程序用。**RoboDK 和驱动进程有时不会自己退出;测试检测到有驱动进程
  在跑(有人连着真机)时,RoboDK 那几份测试自动跳过。

### 4.9 预览窗口和提示音

- 全屏置顶的 Tk 窗口,文字一律英文,站在 1–1.5 m 外看得清。走仿真时默认只占左半屏,右半屏留给
  RoboDK(`--window` 可改)。
- 上面是状态大字、倒计时、执行进度、停下的原因;中间是镜像的摄像头画面,叠加手框、姿势标签、
  检测区域和起点区的边框、READY、方向箭头、保持进度圈;右侧整列是手势图例;底下是按键说明。
  窗口不在前台时用红字提示(这时收不到回车、R、q,但空格照样能叫停)。
- 提示音用 `winsound`,单独一个线程:认到触发、对准成功、倒计时、叫停、进已停止各有各的声。

### 4.10 测试

- **pytest,43 个文件、约 785 个测试函数**,只测外部行为:喂进事件或逐帧结果,看状态怎么变、
  对机械臂接口调了什么、排出了哪件触发。
- **靠三个缝换掉真东西:**假机械臂(`tests/fakes.py`)按安排报碰撞、运动错误、急停;编好的帧和
  识别结果(`tests/vision_fakes.py`)驱动对准、触发判定、识别中断。这些不开 RoboDK、不开摄像头。
- **RoboDK 仿真那几份**在 RoboDK 开着时才跑,没开就跳过,不算失败。
- **回放测试**(`vision_side/replay.py`):录制工具录下视频、逐帧日志和提示时间表(当标注),回放时
  重新跑识别和判定,算识别率、方向判错、误触发、叫停成功率,和上一次逐项比,**不设容差**,
  哪一项变差都报出来。只改判定规则时用逐帧日志,快。录像在 `data/recordings/`,不进 git;
  本机没有数据时跳过。
- **要人在场的**(端到端站着跑、真机上的 `speed_check`、`stop_check`)不进自动测试,手动跑。

## 5. 实现步骤

### 5.1 做法

每一块都走同一个循环:

1. **拷问**:把需求问到能写下来为止,一共问了四十多轮。结论记进 `docs/grill-decisions.md`,
   词记进 `CONTEXT.md`,有取舍的写成 ADR。
2. **原型**:一轮只回答一个问题,约 5 分钟出结果。代码放 `.scratch/`,分支 `prototype/*`,
   数据和结论写进 `notes/` 的结果文件,再回到拷问。
3. **spec 和工单**:两侧各写一份 spec(问题、用户故事、实现决定、测试决定),拆成工单,放在
   `.scratch/robot-side/issues/`、`.scratch/vision-side/issues/`。
4. **实现**:每张票一个分支,每写完一块提交一次;写完按两轴复查(合不合仓库的规矩、合不合 spec),
   再合回 `robot` / `vision`,合回 `main` 之前先问。
5. **上真机实测**,结果写进 `notes/`,推翻的假设回到拷问。

会话之间靠 `handsoff/` 里的交接说明接上。

## 6. 现状和没做完的

**能用的:**仿真里整套流程(启动、对准、全部手势、叫停、已停止、回待命)走得通;JAKA 真机上
启动顺序走通,9-24 用手势跑过上下前后左右。

**还没做或没验的:**

- **真机上三项实测**(`docs/demo-checklist.md`):断连保险(结束程序、结束 RoboDK、拔网线时机械臂停
  不停)、叫停从按下到停住要多久和滑多远、急停和碰撞保护时程序能不能知道。
- **速度**:README 里写着包过的驱动「还没上真机验过」,那是 9-23 写的。仓库外的真机配置副本里已经
  打开了 `program_sets_speed`,9-24 也在真机上调过速度,但 `speed_check` 的结论没有记进文档。
- **识别参数大多是在坐着录的数据上调的。**站着、换人、换光照、离镜头超过 1.5 m 都没系统复核;
  回放基准里七份录像有五份是坐着录的,那些识别率说明不了站着能做到多少。
- **已知挡不住的:**顺手误触发;拳头往上以后手自然张开会被认成叫停(用户选了先改习惯:做完握着拳
  放下,规则不改)。
- **Dobot Nova 5 真机**怎么接还没定,本机 RoboDK 的 Dobot 驱动多半控制不了 V4 固件。
- **`main` 落后 `vision` 13 个提交**,合不合、什么时候合,等用户定。
