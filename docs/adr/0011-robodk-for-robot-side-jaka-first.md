# 机器人一侧改用 RoboDK:先在仿真里跑通,上实机先上 JAKA

原定机械臂一侧直接调两家的官方 Python SDK(JAKA 用 `jkrc`,Dobot 用 `dobot_sdk`),不连实机时用替身和假控制器,第一版先做 Nova 5(ADR-0004)。2026-09-19 用户改为「使用RoboDK 先完成机器人方面的程序,统一JAKA和Dobot」,视觉部分往后放。

**2026-09-20 更新:控真机这一半动摇了。**第一次上 JAKA 实测:驱动连得上、读得到、走得准,但**经 RoboDK 设不了速度**(`setSpeedJoints()`、控制柜倍率、`setParam("Driver","SPEED …")`、程序里的 `CHANGESPEED` 指令四条通道全部无效),实测 1° 的峰值就约 5.5 °/s,超过约定的 ≤5 °/s;演示要的慢速全部落空。仿真那一半不受影响。用户随后定(2026-09-20):**不用官方 SDK 直控,真机仍经 RoboDK 的驱动;速度和加速度由人在示教器上调好,程序不设速度、不管倍率。**本 ADR 因此维持——程序对真机只做「连接、下发一段一段的运动、叫停、读状态」,速度不归它管。代价写在下面的后果里。详见 `docs/grill-decisions.md` 第四节「第一次上 JAKA(2026-09-20)」。

**2026-09-23 更新:设不了速度的原因找到了,JAKA 上速度又归程序管。**用户觉得回待命、点头比左右上下快,要「均匀一点」,在几个办法里选了「包一层驱动」。反编译 RoboDK 的 JAKA 驱动(`v310/JakaDriver.pyc`,v1.1.2)看到:它每收到一行指令,都先把速度重置成写死的关节 100 °/s、直线 100 mm/s,再执行这一行——`SPEED` 那一行确实存下了程序设的速度,下一行运动一进来又被盖掉。所以 9-20 那四条通道全部无效,实际速度一直是 100 × 示教器上的速度倍率(倍率 13% 时关节约 13 °/s,和 9-22 实测对得上);关节 13 °/s 落到伸出去一米的法兰上每秒一两百毫米,回待命、点头因此显得快。

于是:
- **包一层驱动**(`robot_side/drivers/jaka_keep_speed.py`):按文件路径载入原来那份 `.pyc`,只把 `RunCommand` 开头那四行重置(14 条字节码指令)换成空操作,换之前逐条核对,对不上就不启动;程序没设速度时和原驱动一模一样,设了超过原来写死的值就按原来的值,只可能更慢。连真机前把机械臂的驱动路径(`PathDriver`)指到它,断开时换回原来的。
- **机械臂配置 `[speed] program_sets_speed`** 管要不要这么做。开了,演示配置里的速度发给控制柜,实际速度 = 程序设的速度 × 示教器倍率(演示配置 50 mm/s、倍率 25% 时约 12.5 mm/s);没开,照旧全看示教器。仓库里的 `jaka.toml` 已开,用户仓库外那份填了 IP 的副本要自己加。
- **速度均匀:**每个预设动作一个速度;直线段法兰按它走,改姿态的那几段和回待命两段走关节运动,关节速度按指针尖端走同样快现算。
- **每段等多久也跟着改:**速度归程序管以后,按估算用时 ÷ 最低倍率 10% 再 × 2 + 5 秒算,不少于原来固定的 90 秒。
- **只在仿真和离线测试里验过,还没上真机。**上真机先跑 `robot_side.scripts.speed_check`:同一小段各用两个速度走一遍(只转 J6、沿 +Z 抬 50 mm),慢的那遍明显更久才算受控。

因此:
- 机械臂一侧通过 RoboDK 的 Python API(`robodk` 包)来动:仿真时动 RoboDK 里的模型,上实机时由 RoboDK 的驱动去动真机,程序只写一套。前提是驱动能用;查不实,就退到 RoboDK 只做仿真、真机仍走官方 SDK。
- 先在 RoboDK 仿真里把机械臂一侧全部跑通,再约真机:机械臂接口、预设动作、回待命、叫停、报错处理、可达性检查、标定和配置。状态逻辑先用键盘或编好的事件驱动,不开摄像头。
- 上实机先上 JAKA Zu 20(原来写成 Zu 12,2026-09-19 用户更正)。RoboDK 的 JAKA 驱动调用 JAKA 官方的 `jkrc`,有真正的停止指令(`motion_abort`)。
- Dobot Nova 5 怎么接,仿真做完、约 Nova 5 之前再定。本机 RoboDK 5.9.0 的 Dobot 驱动发的是 V3 协议的指令,多半控制不了 V4 固件的 Nova 5;仿真不依赖驱动,现在定了,也要等约到 Nova 5 才能验证。
- 指针偏移、工作台坐标系、待命位姿以机械臂配置(TOML)为准:程序每次启动读 TOML,写进 RoboDK。工作站文件(`.rdk`)只放模型、桌子这类摆设,和机器人一侧的代码一起提交到 `robot` 分支。这样不管 Dobot 怎么接,两台的数都在同一个地方。
- 断连保险按 RoboDK 驱动的做法,程序不另外连控制器;上实机第一件事照旧实测,不生效就只靠实体急停和速度上限兜底。
- 不做替身:仿真按实际速度走、能被中途停止、会求逆解,替身要做的它都有;按需模拟报错(碰撞保护、运动报错、急停被按下)在自动测试里用假机械臂补。程序默认只在仿真里动,要连真机得在启动时明确加开关。空实现留着,不开 RoboDK 时用。

## Considered Options

- **两家官方 SDK 各写一份实现,另做替身和假控制器(原方案):**要写两份实现、两个替代品;替身不做逆解,路点够不够得着只能上实机确认。
- **RoboDK 只做仿真,真机仍走官方 SDK:**仿真和真机是两套代码。现在是驱动不能用时的退路。
- **RoboDK 做仿真,也控制真机(采用):**一套代码;RoboDK 会算逆解,可达性在仿真里就能查。
- Dobot 的接法另有四条路:升级到 RoboDK 6.x、用 `dobot_sdk` 自己写一个 V4 驱动、Dobot 这一台绕过 RoboDK、先不定(采用)。

## Consequences

- **叫停:**阻塞的 `MoveJ` / `MoveL` 在整段运动期间一直占着连接的锁,同一条连接上的 `Stop()` 要等运动走完。所以运动用非阻塞调用,执行线程用 `Busy()` 轮询等到位,叫停时在同一条连接上调 `Stop()`。
  - 2026-09-19 仿真里试过:同一条连接、另开一条连接都 10/10 在 0.5 秒内停住、停在半路(3–28 ms),取同一条连接。数据在分支 `prototype/robodk-stop` 的提交 2adce7b。
  - `MoveL` 发出前会先等上一段走完,期间占着锁,所以执行线程要等 `Busy()` 为 0 再发下一段。
  - 仿真里停住是瞬间的;经驱动叫停要多久、停下前会滑多远,要上实机测。
  - 谁来调 `Stop()`:先发现要停的那个线程,不经过主线程(ADR-0012)。非阻塞 `MoveL` 本身要 63–146 ms 才返回,这期间叫停最坏多等约 0.15 秒,仍在 0.5 秒内。
- **可达性检查(2026-09-19 共用路点原型):**两台用同一套路点、不加平移都够得着。实现时要注意:JAKA 的 `SolveIK` 是数值迭代的,不收敛也会返回,要用正解核对;`MoveL_Test` 之后读回的关节角不是终点;本机 RoboDK 的全局碰撞检查开着,`MoveL_Test` 可能返回碰撞。2026-09-19 定:程序启动时关掉碰撞检查、退出时恢复原来的设置;关了还报碰撞,只记日志、提示。JAKA 离底座很近时逆解不收敛,不专门处理,算够不着。
- **断连:**原定由程序开启 JAKA 的「连接中断即终止运动」;现在连着控制器的是 RoboDK 的驱动,不是我们的程序,所以不再由程序开启。程序经 RoboDK 一次只下发一段,程序崩溃时,机械臂最多走完当前这一段;RoboDK 自己退出、网线断了会怎样,要看驱动和控制器,上实机时分三种实测(结束程序、结束 RoboDK、拔网线)。
- **操作位按 JAKA 重算:**Zu 20 臂展 1780 mm,加指针约 200 mm,人和笔记本要在底座转轴约 2.0 m 以外;原来的 1.05 m 是按 Nova 5(臂展 850 mm)算的。型号更正为 Zu 20 以后,用户确认 2.0 m 也站得开(2026-09-19)。
- **标定(JAKA):**指针偏移仍在 JAKA 控制器上用示教法标,由用户把控制器上显示的数抄进机械臂配置;工作台坐标系的角度,由读数小脚本经 RoboDK 读当前位姿算出。程序不直接连控制器。
- **JAKA 驱动能不能连控制器 1.7.2,文档没写,要实机试。**驱动在 RoboDK 自带的 Python(3.10)里跑,和项目的 Python 3.13 分开。
- **仿真默认比实际快:**RoboDK 的仿真速度默认是 5 倍;要按真实耗时跑时,设成 1 倍。
- **速度不归程序管(2026-09-20):**演示配置里的速度只用于仿真;真机上的速度、加速度由人在示教器上调好,所以仿真的耗时和真机不会一致,安全也不再靠程序限速,而是靠控制柜上设的值、慢速、急停和距离。演示前检查清单里要核对这一项。(2026-09-23 更新:JAKA 开了 `program_sets_speed` 以后,程序设的速度到得了控制柜,再乘示教器倍率;倍率仍由人在示教器上调,加速度仍是原驱动写死的值。)
- **还没改的已定决策:**Dobot 的速度换算(ADR-0005)、Dobot 的启动顺序、Nova 5 的核实清单、假控制器。这些随 Dobot 怎么接一起定,见 `docs/grill-decisions.md` 第三节。
- **ADR-0004 里「先做 Nova 5 的实现」由本 ADR 取代。**演示仍在 Nova 5 上做(用户:「演示还在Nova5上做,现在优先做JAKA」),所以约 Nova 5 之前,一定要定下 Dobot 怎么接。
- **调研:**`docs/grill-decisions.md` 第四节「RoboDK 调研(2026-09-19)」。
